# Variation Draft — 계좌 유형

## 1. 목적

일반계좌·안전계좌·수탁계좌와 관련된 기존 Process 차이를 공식 Source 범위에서만 구조화한다. 계좌 유형 구분의 존재, 상세 판별 기준, 유형별 서류 세트를 서로 분리하며 기관·지점·제출 방식 차이는 포함하지 않는다.

## 2. 적용 대상 Process

- `07-account-opening`: `AO-03`~`AO-04`
- `08-account-supplement`: `AS-01`~`AS-09`의 계좌 유형별 차이 검증 후보
- `09-account-closure`: `AC-01`~`AC-08`의 계좌 유형별 차이 검증 후보
- `10-balance-certificate`: `BC-01`~`BC-09`의 계좌 유형별 차이 검증 후보

Process 08·09에는 계좌 유형별 상세 적용 차이를 직접 확인할 Source가 없다. Process 10에는 일반·안전·수탁·기타 계좌 요청 경로가 `PROVISIONAL`로 보강됐으나 세부 실행 Rule은 `UNKNOWN`이다.

## 3. 공식 Source 범위

- `sources/notion/n-05-07.md`: `5.7/08`, `5.7/11`, `5.7/15`
- `sources/notion/n-05-08.md`: 계좌개설 보완 Task
- `sources/notion/n-05-09.md`: 계좌해지 Task
- `sources/notion/n-05-10.md`: 잔액증명서 발급 Task
- `sources/notion/n-06.md`: `6.7`~`6.10` Definition Map

- Process 07~10의 위 기존 Task

`N-06`과 `N-08`은 업무 정의·Roadmap 연결을 보조하지만 계좌 유형별 상세 차이를 제공하지 않는다.

## 6. 계좌 유형 판별 기준

- `N-05-07/5.7/08`은 계좌 유형 확인 Task의 존재를 직접 지원한다.
- `N-05-07/5.7/15`은 일반계좌·안전계좌 명칭과 서류 차이 확인 Task를 직접 지원한다.
- 일반·안전계좌의 판별값, 선택 조건, 판단 우선순위와 최종 판단 주체는 `UNKNOWN`이다.
- 수탁 여부는 `5.7/11`에서 확인·보류되므로 수탁계좌 판별 기준을 확정하지 않는다.

## 7. Input 차이

- 공통 Input은 `AO-03`의 계좌 관련 정보와 `AO-04`의 신청서류 후보 범위다.
- 일반·안전계좌별 추가 Input과 수탁계좌의 적용 판단 Input은 확인되지 않아 `UNKNOWN`이다.

## 8. 서류 차이

- 일반계좌와 안전계좌 사이에 서류 차이를 확인하는 단계의 존재는 `CONFIRMED`다.
- 각 유형의 상세 문서명, 수량, 원본·사본 기준, 날인 기준은 Source에 없어 `PROVISIONAL` 또는 `UNKNOWN`이다.
- 수탁계좌 서류는 확인되지 않아 `UNKNOWN`이다.
- 일부 서류 차이를 전체 필수서류 세트로 일반화하지 않는다.

## 9. Decision 차이

- 일반·안전계좌 유형을 식별하고 서류 후보를 달리 검수하는 Decision 지점은 확인된다.
- 일반·안전계좌 판별 조건은 `UNKNOWN`이다.
- 수탁계좌 적용 여부, 일반·안전계좌와의 관계, 보류 해제 조건은 `UNKNOWN`이다.

## 10. Actor 차이

- Process 07의 기존 `AO-03`~`AO-04` Actor는 지원팀이다.
- 계좌 유형별로 담당 관리역, 지원팀 또는 외부 주체의 책임이 달라진다는 직접 근거가 없어 새 Actor를 배정하지 않는다.
- 수탁계좌의 개설·보완·해지·잔액증명서 처리 주체는 `UNKNOWN`이다.
- 안전계좌의 오픈플랫폼팀 연계는 `PROVISIONAL` 후보 Actor이며, 지원팀 포함 범위와 표준 책임 주체는 `UNKNOWN`이다. (`N-05-07` Claude Finding Enrichment)
- Process 09의 지원팀 수행은 단일 확인 사례이므로 계좌 유형별 공통 Actor 근거로 사용하지 않는다.

## 11. 제출·접수 차이

- 계좌 유형 자체에 따른 제출·접수 방식 차이는 지정 Source에서 확인되지 않아 `UNKNOWN`이다.
- 기관·지점과 방문·퀵·메일·팩스 등 처리 방식은 `V1-C` 검토 대상으로 분리하며 이 초안의 Rule로 사용하지 않는다.

## 12. Output 차이

- Process 10의 일반·안전·수탁·기타 계좌 요청 경로 존재는 `PROVISIONAL`이지만 유형별 Output 명칭이나 구성 차이는 `UNKNOWN`이다.
- 수탁계좌의 Output과 수령 주체도 `UNKNOWN`이다.
- Process 08·09·10의 공통 Output을 계좌 유형별 Output으로 재분류하지 않는다.

## 13. 완료조건 차이

- Process 07의 기존 완료조건 외에 일반·안전계좌별 완료조건 차이는 확인되지 않았다.
- 수탁계좌의 개설 완료, 보완 완료, 해지 완료와 유형별 잔액증명서 발급 완료 조건은 모두 `UNKNOWN`이다.

## 14. 보완·Exception 차이

- Process 08의 기존 보완 흐름은 계좌 유형별 차이를 직접 명시하지 않는다.
- Process 09·10도 계좌 유형별 별도 Exception이나 복귀점을 직접 제공하지 않는다.
- 일반·안전·수탁계좌별 보완 주체, 수정 서류, 복귀 Task와 종료조건 차이는 `UNKNOWN`이다.

## 15. 적용·제외 Task

- 직접 Source가 계좌 유형별 ADD 또는 EXCLUDE를 명시한 항목은 0건이다.
- `AO-03`~`AO-04`는 공통 Process의 기존 Task이며 Variation에서 새로 추가하지 않는다.
- Process 08·09의 기존 Task를 특정 계좌 유형에서 임의로 적용하거나 제외하지 않는다.
- Process 10의 유형별 요청 경로는 기존 `BC-01`~`BC-06` 안의 `PROVISIONAL` 분기이며 새 Task가 아니다.

## 16. UNKNOWN

- 일반·안전계좌 판별값과 선택 조건
- 일반·안전계좌별 전체 필수서류 세트
- 일반·안전계좌별 Input, Output, Actor, 완료조건, Exception 차이
- 수탁계좌의 공식 정의와 적용 대상
- 수탁계좌 개설·보완·해지·잔액증명서의 수행 주체와 필요 서류
- 수탁계좌 완료조건과 일반·안전계좌와의 관계

## 17. 인터뷰·CASE 검증 필요항목

- 일반계좌와 안전계좌를 구분하는 공식 필드와 판단 주체는 무엇인가.
- 일반·안전계좌별 필수서류 목록과 차이의 공식 근거는 무엇인가.
- 각 유형에서 Process 08·09·10의 Task 적용 또는 완료조건이 달라지는가.
- 수탁계좌라는 유형이 공식적으로 존재하며 어떤 경우에 적용되는가.
- 수탁계좌의 개설·보완·해지·잔액증명서 수행 주체와 결과 수령자는 누구인가.

CASE 답변은 Evidence로만 사용하고 추가 공식 Source 확인 전에는 공통 Variation Rule로 확정하지 않는다.
