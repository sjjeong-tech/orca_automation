# CI5 — E2E-03 Conversation Script (Subagent B, Baseline)

TEST Transaction ID: `CI5-E2E03-ALPHA-LOOP-001` / Prefix: `[TEST][ALPHA-LOOP]`
재사용 FUND: `[TEST][CI1-PILOT] 가상조합1호`(신규 FUND 생성하지 않음)
요청자·담당 관리역(TEST): Workspace Person `정상준`(기존 CI1~CI4 TEST와 동일 인물 재사용)

## Phase 0 — 자연어 업무 요청

| turn | 발화자 | 내용 |
|---|---|---|
| 1 | 사용자 | "고유번호증 신청을 진행해줘." |
| 1 | Agent | `request_type=고유번호증 신청` 추출, `related_fund` 없음 → **차단**, 질문: "어느 조합의 고유번호증 신청을 진행할까요?" |
| 2 | 사용자 | "가상조합1호요." |
| 2 | Agent | FUND 검색 → 기존 TEST FUND 1건 매칭(SINGLE_MATCH) → 중복 확인(동일 조합+업무유형의 미완료 Request 없음, NO_DUPLICATE_FOUND) → 여전히 `requester`, `fund_manager`, `document_status` 누락(3개, `max_questions_per_turn=3` 이내) → 질문: "요청자, 담당 관리역, 서류 전달 상태(미전달/일부 전달/전달 완료/보완 필요)를 알려주세요." |
| 3 | 사용자 | "요청자는 정상준이고 담당 관리역도 정상준입니다. 서류는 아직 미전달이에요." |
| 3 | Agent | 필수정보 충족(`required_fields_complete`) → Preview 생성: Request 요약 + Task 6건 예정 + Planned Write=7(Request 1 + Task 6) + Actual Write=0 → "이 내용으로 등록할까요?" |
| 4 | 사용자 | "승인합니다. 생성해주세요." |
| 4 | Agent | 명시적 승인 토큰(`승인`, `생성`) 확인 → COMMIT → Request 1건 + Task 6건 생성, Actual Write=7 |

**검증**: Preview 전 Write 0(turn 1~3 동안 Notion 호출 없음), FUND 0건 재차 발생하지 않음(기존 FUND 재사용으로 CREATE 회피), 명시적 승인 전 COMMIT 없음.

## Phase 1 — P03-T01 요청정보·착수조건 확인

- 자동 착수: Task 생성 즉시 `T01=진행 중`(Actor=지원팀), 나머지 5건 `시작 전`, Request `진행 중`으로 전환(RQ-ACTIVE 진입, `필수 Task 착수` Trigger)
- 조합 유형·GP유형·공동여부는 이번 알파에서 Metadata로만 취급(분기 없음) — 지원팀이 Notion 외부에서 확인했다고 가정하고 Task 완료조건에만 반영
- 사용자: "조합 폴더 확인했고 기본정보 이상 없습니다." → 완료조건 충족 → `T01=완료`, `T02=진행 중` 자동 전환

## Phase 2 — P03-T02 제출서류 수령·누락 검수 (핵심 검증: `일부 전달` vs `보완 필요`)

| turn | 발화자 | 내용 | 반영 |
|---|---|---|---|
| 1 | 사용자 | "서류 일부 도착했어요." | 서류 상태(Request)=`일부 전달` |
| 2 | Agent(검수) | 도착분 검수 결과 누락 발견 | **친도점**: `보완 필요`로 바꾸면 "얼마나 왔는지"(일부/전체) 정보가 사라짐. Baseline에서는 서류 상태를 `보완 필요`로 전환하고, "몇 건 중 몇 건 도착했는지"는 Task Blocker 텍스트에만 기록 |
| 2 | Agent | | Task Blocker=`누락서류: OO증빙 1건(전체 3건 중 2건 수령)`, Actor=`관리역 확인`, Next=`누락서류 보완 요청` |
| 3 | 사용자 | "나머지 서류 보냈습니다." | Blocker 해소(`null`), Actor=`지원팀`, 서류 상태(Request)=`전달 완료`, Next=`보완 수령분 재검수` |
| 4 | 사용자 | "확인했습니다, 문제 없습니다." | 완료조건 충족 → `T02=완료`, `T03=진행 중` 자동 전환 |

## Phase 3 — P03-T03 신청서류 작성·날인본 확인 (Actor 전환: 지원팀→GP→지원팀)

| turn | 발화자 | 내용 | 반영 |
|---|---|---|---|
| 1 | Agent | 신청서 초안 작성 후 GP에 날인 요청 | Actor=`GP`, Blocker=`날인 대기`, Next=`날인본 회신 대기` |
| 2 | 사용자 | "날인본 왔는데 조합 도장이 아니라 개인 도장이 찍혀있어요." | Blocker=`날인 오류(조합인감 아님)`, Actor=`GP`(재요청 유지), Next=`정상 날인본 재요청` |
| 3 | 사용자 | "재날인본 받았고 확인해보니 정상입니다." | Blocker 해소, Actor=`지원팀`, Next=`제출 가능 여부 최종 판정` |
| 4 | 사용자 | "제출 가능합니다." | 완료조건 충족 → `T03=완료`, `T04=진행 중` 자동 전환 |

**검증**: 날인 오류 발생 시 신규 Task를 만들지 않고 T03 하나에서 계속됨. Root(E2E-03)에 없는 별도 상태·Rule 추가 없음(Task 상태 옵션 3개 그대로, GP 재요청은 Actor 값만으로 표현).

## Phase 4 — P03-T04 세무서 제출 준비·접수 (기관 추가요청 시뮬레이션)

| turn | 발화자 | 내용 | 반영 |
|---|---|---|---|
| 1 | Agent | 제출 세트 구성 후 세무서 제출 시도 | Actor=`지원팀`, Next=`제출 세트 구성 및 세무서 제출` |
| 2 | 사용자 | "세무서 갔는데 서류 하나 더 필요하다고 하네요." | Blocker=`세무서 현장 추가요청(주소증빙 추가)`, Actor=`관리역 확인`, Next=`추가서류 확보 후 접수 재개` |
| 3 | 사용자 | "추가서류 챙겨서 다시 접수했고 접수증 받았습니다." | Blocker 해소, Actor=`지원팀`, 완료증빙=`접수증 스캔본 확인`, Next=`처리완료 통지 대기` |
| 4 | (자동) | 완료조건 충족 | `T04=완료`, `T05=진행 중` 자동 전환 |

## Phase 5 — P03-T05 결과물 수령 (접수 완료 ≠ 전체 완료 구분)

| turn | 발화자 | 내용 | 반영 |
|---|---|---|---|
| 1 | (자동) | Task 활성화 | Actor=`외부기관`, Next=`처리완료 통지 대기` — **이 시점에서 Request는 아직 진행 중이며 완료가 아님**(T06 남음) |
| 2 | 사용자 | "처리완료 문자 왔어요." | Actor=`지원팀`, Next=`세무서 방문해 고유번호증 수령` |
| 3 | 사용자 | "고유번호증 수령했습니다." | 완료증빙=`고유번호증 실물 수령 확인`, 완료조건 충족 → `T05=완료`, `T06=진행 중` 자동 전환 |

## Phase 6 — P03-T06 스캔·저장·관리역 전달 (E2E 완료)

| turn | 발화자 | 내용 | 반영 |
|---|---|---|---|
| 1 | (자동) | Task 활성화 | Actor=`지원팀`, Next=`스캔 후 지정 폴더 저장` |
| 2 | 사용자 | "스캔해서 폴더에 저장했고 관리역님께 전달했습니다." | 완료증빙=`스캔본 저장 경로 확인, 관리역 전달 확인`, 완료조건 충족 → `T06=완료` |
| 3 | (자동) | 6개 Task 전체 완료 확인(RC-01~06 상당) | Request 상태 → `완료` — **T06 완료 이후에만 가능함을 순서로 보장** |
