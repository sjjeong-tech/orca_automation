# 외근 산출물 Evidence 조사 분석

## 1. 목적과 범위

이 문서는 2026-07-25 기준 Google Drive `외근_세무서, 은행` Root에서 접근 가능한 전체 하위 트리를 파일 메타데이터 중심으로 조사한 결과다.

- 조사 Root: `외근_세무서, 은행`
- 조사 범위: Root 및 모든 직접·간접 하위 폴더
- 조사 방식: Folder ID를 따라 직접 자식을 재귀 조회
- 원문 본문 열람: 0건
- Drive File ID·직접 URL의 Git 기록: 0건
- Drive·Notion Write: 각각 0건
- Canonical·Process Rule·Notion Schema 변경: 0건

현재 Canonical Workmap에는 CP-08 Work Item이 없으므로, 이번 결과는 독립 Evidence Discovery로 기록한다. Workmap 반영은 후속 판단 후보이며 이번 조사에서 수행하지 않았다.

> 이 문서는 외근 산출물의 관찰·추론 Evidence이며,
> 산출물 부재를 업무 미수행으로 간주하지 않고,
> 미검증 추론을 Process Rule로 확정하지 않는다.

## 2. 조사 방법과 한계

파일명·상대 경로·폴더 날짜·MIME 유형·생성일·수정일만 사용했다. 파일명에서 직접 확인되는 산출물은 `Observed`, 그 존재로 예상되는 업무 단계는 `Inferred`로 분리했다.

FUND 후보는 파일명에서 업무·산출물 접미 표현을 제거한 검색 보조값이다. `전체관리조합` 1,231행과 대조했으며, 정확히 한 건 일치한 경우에만 `EXACT_1`로 기록했다. 유사 일치는 자동 연결하지 않고 사람 확인 대상으로 남겼다.

한계는 다음과 같다.

- 파일 본문을 읽지 않아 제출 내용, 기관 접수 사실, 문서 유효성 및 E2E 완료를 확정할 수 없다.
- 파일 부재는 업무 미수행이나 증빙 부재를 뜻하지 않는다.
- 폴더명 날짜는 업무 수행일이 아니라 정리일일 수 있다.
- 민감정보 가능성이 있는 파일명 14건은 CSV에서 마스킹했다.
- 외근 산출물 Root는 조합별 Fund Root가 아니다.

## 9. E2E·Evidence Contract에 활용 가능한 근거

- `SUBMISSION_PACKAGE`: 신청·제출 준비 단계의 후보 Evidence
- `RECEIPT`: 기관 접수 완료 판정에 사용할 수 있는 후보 Evidence
- `RESULT_DOCUMENT`: 결과물 수령 단계의 후보 Evidence
- `SECURITY_CARD`: 보안카드 발급·수령의 후보 Evidence
- `SUPPLEMENT`: 보완 요청과 재진행 구간의 후보 Evidence
- `BANKBOOK_COPY`: 계좌개설 완료 산출물 후보

이 연결은 Evidence Type과 실제 파일군을 후속 검증하기 위한 근거다. 필수 증빙, 완료조건, 보존기간 또는 자동화 Rule을 이번 조사로 확정하지 않는다.

## 10. 아직 확정하면 안 되는 Rule

- 신청서류 파일이 있으면 실제 기관 접수가 완료됐다는 Rule
- 접수증 한 건으로 전체 Request가 완료된다는 Rule
- 결과 문서 파일이 있으면 관리역 전달까지 완료됐다는 Rule
- 특정 날짜 폴더의 모든 파일이 같은 날 수행된 업무라는 Rule
- 파일이 없으면 해당 단계가 수행되지 않았다는 Rule
- 유사 조합명이 같은 FUND라는 Rule
- 한 사례의 산출물 구성이 모든 기관·조합에 공통이라는 Rule

## 11. Open Gap

1. 추천 사례의 조합 Root에서 원본·제출본·접수증·결과물 연결을 재검증해야 한다.
2. FUND `SIMILAR_1` 3건과 `NOT_FOUND` 22건은 사람이 표준명을 확인해야 한다.
3. 분류 불가 85건은 필요성이 인정되는 범위에서만 사람이 파일명을 재검토해야 한다.
4. 생성일·수정일과 실제 수행일의 관계가 확인되지 않았다.
5. 결과물 전달, 실물 수령, 완료 승인 흔적은 파일명만으로 확인할 수 없다.
6. 동일 이름 파일의 버전·중복 여부는 File ID 중복과 별개로 확인이 필요하다.

## 12. 후속 Physical·Live 검증안

1. 업무별 추천 후보 중 1건을 선택한다.
2. 해당 Fund Root의 비민감 메타데이터로 Source Folder를 확인한다.
3. 신청·접수·결과·전달 Evidence를 업무 실행자와 함께 대조한다.
4. Notion Request·Task 상태와 Drive Evidence 발생 시점을 Replay한다.
5. 두 건 이상에서 반복 확인된 항목만 공통 Rule 후보로 올린다.
6. 기관·조합별 차이는 `조건부`, `기관별`, `예외`로 분리한다.
