# 표준규칙

> CASE-01 한 건을 기반으로 시작한 Day 1 초안이다. CASE-02~04 분석 후 규칙의 범위와 예외를 검증한다.

## 공통

- Notion에서 업무 상태, 책임, 다음 행동, 목표일, 대기 대상을 관리한다.
- 실제 작업파일, 제출본, 접수증, 결과물은 Google Drive에서 관리한다.
- Git에는 표준규칙, 비식별 사례, Agent 지침만 기록한다.
- 확인되지 않은 사실은 추정하지 않고 `확인 필요`로 남긴다.
- 민감정보는 저장소와 Tracker에 기록하지 않는다.
- 업무 결과 수령과 실물·시스템 후속조치 완료를 구분해 추적한다.
- 동일 Notion 레코드의 최종 쓰기는 한 Agent만 수행한다.

## 조건부

- 조합 법적 형태, GP 유형, 계좌 유형에 따라 요구서류와 절차가 달라질 수 있으므로 사례별로 확인한다.
- 보완 요청이 발생하면 요청 주체, 요청 내용, 회신 기한, 재제출 여부를 기록한다.
- 실물 수령이나 등록 후속조치가 있는 업무는 `결과 수령` 후 `후속 처리` 단계를 거친다.

## 기관별

- 세무서, 은행, 지점별 요구사항은 공통규칙으로 일반화하지 않고 기관명·지점명과 확인 시점을 기록한다.
- CASE-01의 농협 반포역지점 경험은 다른 지점에 자동 적용하지 않는다.

## 예외

- 표준 흐름과 다른 처리에는 사유, 승인 또는 확인 근거, 후속 영향을 기록한다.
- 예외를 새 표준으로 전환하려면 복수 사례에서 재현 여부를 검토한다.

## 검증 대기

- CASE-02~04에서 단계 순서와 필수 산출물의 공통성 확인
- 법적 형태·GP 유형·계좌 유형별 요구사항 차이 확인
- 세무서 및 은행 지점별 보완 패턴 확인
