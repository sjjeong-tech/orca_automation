# 화면 역할 분리안

## 결론 — 5개가 아니라 3개 + 1

TAP은 화면 후보 5개를 제시했다. 실측 결과 **3개 + 기술 상세 1개**로 줄인다.

근거:

- 화면 4(실행 결과)는 실제 Notion Write가 있어야 의미가 있다. 승인 전이므로 **화면 3의 하위 상태**로 두고, Write 승인 후 독립 화면으로 승격한다
- 화면 1(요청함)과 화면 2(업무 실행)를 완전히 분리하면 요청 3건짜리 Pilot에서 왕복 비용만 늘어난다. **좌측 고정 목록 + 우측 본문**으로 한 화면에 둔다

| 화면 | 이름 | 주 사용자 | 핵심 결정 1개 |
|---|---|---|---|
| A | 업무 실행 | 지원팀 담당자 | **지금 내가 무엇을 해야 하는가** |
| B | 반영 검토 | 담당자 → 승인자 | **Notion에 써도 되는가** |
| C | 실행 결과 | 승인자 | **실제로 무엇이 생겼고 중복은 없는가** |
| D | 기술 상세 | Process Owner | **Contract를 지켰는가** |

D는 화면이 아니라 **A·B·C 어디서든 열리는 Drawer**다. 기본 접힘.

## 화면 A — 업무 실행 (기본 진입)

```
┌──────────────┬──────────────────────────────────────────┐
│ 요청 3건      │  [요청명]              [전체 상태 배지]    │
│ ─────────────│  DUMMY-FUND-B · 고유번호증 신청           │
│ ▸ REQ-001 ●  │                                          │
│   REQ-002    │  ┏━━━ 지금 해야 할 일 ━━━━━━━━━━━━━━━┓  │
│   REQ-003    │  ┃ 담당: 사람 확인                    ┃  │
│              │  ┃ 할 일: 유효한 날인본 원본 재수집    ┃  │
│              │  ┃ 막힌 이유: 날인본 원본 미확보       ┃  │
│              │  ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛  │
│              │                                          │
│              │  확인 질문                                │
│              │  "날인본 원본과 필수 날인 위치가          │
│              │   확인됐나요?"          [예] [아니오]     │
│              │                                          │
│              │  자료 상태                                │
│              │  제출 서류 세트  ✓ 확인됨                 │
│              │  날인본 원본     ✗ 없음  ← 이것 때문      │
│              │                                          │
│              │  Task 3건        [펼치기]                 │
│              │  진행 흐름       접수 → 검토 → 확인 → 중단 │
│              │                                          │
│              │  [반영 검토로 →]  (Gap 2건이라 비활성)     │
│              │   ↳ 조합 연결 대상 없음 / 중복 기준 미확정 │
└──────────────┴──────────────────────────────────────────┘
```

핵심 규칙:

- **1440px 첫 화면에 "지금 해야 할 일" 블록이 반드시 들어간다.** 스크롤 없이
- 담당 · 다음 Action · 막힌 이유는 **서로 다른 시각 영역**
- 자료 상태는 부족한 항목이 왜 문제인지까지 표시 (질문 6)
- Kanban은 기본 접힘. 빈 Column이 화면을 먹지 않게
- 다음 화면 버튼이 비활성이면 **이유를 버튼 바로 아래** 표시

## 화면 B — 반영 검토

핵심 결정: Notion에 써도 되는가.

| 영역 | 내용 |
|---|---|
| 상단 | 반영 가능 여부 + Blocking Gap 개수 (2건) |
| Gap 목록 | Gap별 — 무엇이 / 왜 막는가 / 누가 풀 수 있는가 |
| 생성 예정 | Request 1건 · Task N건 (접힌 카드) |
| 관계 | Request ↔ Task 연결 방식 |
| 중복 조회 | 같은 Transaction이 이미 있는가 |
| 승인 | Gap 0건일 때만 활성. 비활성 시 이유 표시 |
| 고정 표시 | **Notion 반영 0건 / 운영 반영 0건** |

## 화면 D — 기술 상세 (Drawer)

Canonical Stage · Schema · Property Mapping · Raw JSON · Manifest · Commit · Audit.
A·B·C 우상단 버튼으로 열림. 기본 접힘. 내부 영어 상태값은 전부 여기.
