# 사용자 역할과 Job-to-be-Done

## 역할 4종

| 역할 | 이 Pilot에서의 비중 | 이유 |
|---|---|---|
| **지원팀 담당자** | **주 사용자** | 실제 Task를 수행하는 유일한 실행 주체. Actor·Next Action·Blocker가 전부 이 사람 화면 |
| 검토·승인자 | 2차 | Notion 반영 승인 Gate만 담당. 화면 체류 시간 짧음 |
| 운영팀 관리역 | 관찰자 | 요청을 넣고 진행 상황만 확인. 이 Pilot에서는 요청 원문 제공자 |
| Process Owner | 검증자 | Contract·Canonical Stage·Raw JSON 확인. 기술 상세 화면만 사용 |

**첫 Pilot의 주 사용자는 지원팀 담당자로 둔다.** 근거: 10개 핵심 질문 중 6개(2·3·4·5·6·8)가
실행 담당자의 질문이고, 나머지 4개는 승인·검증 시점의 질문이다.

## Job-to-be-Done

### 지원팀 담당자

| 항목 | 답 |
|---|---|
| 언제 여는가 | 업무 시작 시, 그리고 외부 회신(세무서·은행·GP)이 올 때마다 |
| 어떤 결정을 위해 보는가 | "지금 내가 손댈 수 있는 Task가 무엇인가" |
| 가장 먼저 알아야 할 것 | 내가 Actor인 Task와 그 Blocker |
| 어떤 행동을 하는가 | Evidence 확인 · 사람 확인 질문 응답 · 다음 Action 수행 |
| 언제 다른 화면으로 가는가 | Task가 전부 처리돼 Notion 반영 준비가 됐을 때 |
| 무엇을 완료로 보는가 | **완료 후보까지만.** 완료 선언은 하지 않는다 |

### 검토·승인자

| 항목 | 답 |
|---|---|
| 언제 여는가 | 담당자가 반영 준비 완료를 알렸을 때 |
| 어떤 결정을 위해 보는가 | "이걸 Notion에 써도 되는가" |
| 가장 먼저 알아야 할 것 | Blocking Gap 개수와 그 내용 |
| 어떤 행동을 하는가 | 생성 예정 Record 확인 → 승인 또는 반려 |
| 무엇을 완료로 보는가 | 승인 문구 발급 |

### 운영팀 관리역

| 항목 | 답 |
|---|---|
| 언제 여는가 | 요청 후 진행 상황이 궁금할 때 |
| 가장 먼저 알아야 할 것 | 내 요청이 막혔는가, 막혔다면 누구 때문인가 |
| 어떤 행동을 하는가 | 없음 (읽기 전용). 필요 시 자료 보완 |

### Process Owner

| 항목 | 답 |
|---|---|
| 언제 여는가 | Contract 위반 의심 시, 릴리스 검증 시 |
| 가장 먼저 알아야 할 것 | Canonical Stage 매핑과 Write Count |
| 어떤 행동을 하는가 | Raw JSON·Manifest·Audit 확인 |

## 설계에 미치는 영향

1. **첫 화면은 지원팀 담당자 기준으로 연다.** 승인·기술 상세는 별도 경로
2. **내부 영어 상태(`APPROVAL_BLOCKED`, `NO_MATCH`)는 Process Owner 화면으로 보낸다.**
   담당자 화면은 한국어 Label
3. **운영팀 관리역용 읽기 전용 뷰는 이번 Pilot 범위 밖.** 담당자 화면을 공유해서 대체
